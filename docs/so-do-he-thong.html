CS Console: hệ thống gồm những gì và nối với nhau ra sao

Web theo dõi deal triển khai cho team CS của Base.vn. Frontend là file tĩnh trên Vercel, backend và dữ liệu nằm trên Supabase, dữ liệu deal đổ về mỗi giờ từ Google Sheet qua Apps Script. Không dùng framework: HTML, CSS và JavaScript thuần.

1. Bức tranh tổng thể

Bốn khu vực: người dùng, Vercel (giao diện), Supabase (xử lý + dữ liệu), Google (đăng nhập, nguồn deal, gửi mail). Số trong vòng tròn là thứ tự một lần mở console.

2. Bên trong giao diện: app.js và ui.js

Đây là chỗ "không theo framework". app.js tự vẽ toàn bộ giao diện và bị khoá, không ai được sửa. Mọi thay đổi về sau đều nằm ở ui.js: nó canh những gì app.js vẽ ra rồi đắp thêm lên.

Các mục trong ui.js (tìm theo tiêu đề khối comment)

  • A–D: modal Gia hạn/Dừng, nút trên bảng deal, chỉnh 2 card CR, màn Request
  • Kết nối Claude: tạo, thu hồi link MCP
  • Quản trị: feedback, todo, danh sách CS, bảng Cộng phước
  • Trợ lý CS (cuối file): "Vì sao?", lịch đánh giá, mô phỏng Career path
  • Product tour: Driver.js, 28 bước

Cache-busting

index.html nạp file kèm ?v=N (ví dụ ui.js?v=71). Mỗi lần sửa CSS/JS phải tăng số này, nếu không trình duyệt người dùng vẫn chạy bản cũ.

3. Một con số deal đi từ CRM tới màn hình

Số deal không nhập tay. Nó chảy từ CRM qua sheet của chị Chi, được Apps Script kiểm rồi mới vào database. Số CS tự nhập (%Active, %Output…) nằm bảng riêng, chỉ ghép vào lúc xem.

4. Đăng nhập và phân quyền

  1. Người dùng bấm nút Google. Google trả id_token, chỉ chấp nhận email @base.vn.
  2. app.js gửi token đó lên Edge Function api. Function hỏi Google (tokeninfo) để xác minh, rồi cấp một vé phiên CST1.… ký bằng SESSION_SECRET, hạn 30 ngày. Các lần sau chỉ gửi vé này.
  3. Mọi hàm SQL api_* nhận email đã xác minh và chỉ trả deal của email đó. Email có trong bảng app_admins thấy thêm phần Quản trị và các tool admin_* trên MCP.
  4. Link MCP: mỗi người tự tạo trong mục "Kết nối Claude". Database chỉ lưu mã băm SHA-256 của khoá; thu hồi khoá là link chết ngay.

5. Quy tắc bị chép ở nhiều nơi

Rủi ro lớn nhất khi bàn giao. Cùng một quy tắc được viết lại ở nhiều file vì app.js không được sửa và database, MCP cũng cần tự tính. Sửa một chỗ mà quên chỗ khác thì giao diện, Claude và career path ra ba con số khác nhau.

Chỉ frontend tự động. Ba phần còn lại phải làm tay, và quên bước nào thì phần đó vẫn chạy bản cũ.

Test chạy bằng cd tests && npm install && npm test: quy tắc CR, MCP server, đồng bộ sheet, mail, và smoke test giao diện trên Chromium. Không đặt package.json ở gốc repo vì Vercel đang deploy kiểu tĩnh.

Điểm dễ vấp

  • Không sửa app.js. Cần đổi hành vi thì vá ở ui.js; thật sự không vá được thì hỏi admin.
  • Comment đầu config.js ghi "bản test, không merge vào main" là comment cũ. Nhánh main hiện đang trỏ thẳng Supabase.
  • Code.gs (Apps Script Web App, nằm ngoài repo) là backend cũ, đã được Edge Function api thay thế.
  • Đổi project Supabase thì phải sửa cùng lúc config.js, vercel.json, netlify.toml.
